# Clase 02 — Problem Challenge

**Objetivo:** aprender a identificar, describir y validar correctamente un problema, y aplicar el framework JTBD para enfocar el MVP.

---

## ¿Qué es un problema?

- Punto de partida de todo proyecto
- Su resolución define el propósito del proyecto
- Hay que definirlo bien para no malgastar tiempo/recursos

**Esquema:** `CAUSAS → PROBLEMA → EFECTOS`

> Ver desarrollo completo en [[Problema]]

## ¿Qué NO es un problema?

Una app · una página web · un producto · una solución tecnológica · una plataforma · un bot

👉 Todo eso son **soluciones**, no problemas.

## Cómo identificar y describir un problema

- Se identifica con **causas** y **consecuencias** (árbol de problemas)
- Se plantea como una **hipótesis** de un suceso con impacto negativo
- Oraciones cortas y objetivas, con datos reales si hay
- **NO** debe incluir la solución, ni asunciones, ni prejuicios

**Estructura simple:**
```
[Usuario específico] tiene el problema de [situación concreta]
cuando [contexto], lo que genera [impacto negativo].
```

**Ejemplo:** Estudiantes de primer año tienen el problema de olvidar fechas de entrega cuando usan múltiples plataformas, lo que genera estrés y bajo rendimiento académico.

## Características de un buen problema (para MVP)

| Característica | Qué significa |
|---|---|
| Específico | No "la gente pierde tiempo" → sí "estudiantes pierden tiempo organizando entregas en múltiples plataformas" |
| Relevante | Genera frustración, costo o ineficiencia real |
| Validable en corto plazo | Se puede probar con usuarios reales en ~2 meses |
| Enfocado | Un segmento concreto, no "todos" |

## Definir el problema en un MVP

Antes de construir nada, el equipo responde: **¿qué problema real, relevante y validable estamos resolviendo?**

El [[MVP]] no busca el producto completo, busca validar:
- Si el problema existe
- Si alguien quiere resolverlo
- Si la solución propuesta tiene sentido

---

## JTBD (Jobs to be Done)

> Ver desarrollo completo en [[JTBD]]

- Framework para no confundir **solución** con **problema real**
- Ejemplo: "queremos hacer una app para gestionar proyectos" → eso ya es una solución, no un problema ni un Job

**Insight clave:** el problema no es "no existe una app", el problema es "la coordinación en equipos es caótica".
